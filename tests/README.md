# Pub/Sub 高频并发送达率测试

## 构建与运行

```powershell
cmake -S tests -B tests/build -DCMAKE_BUILD_TYPE=Release
cmake --build tests/build --config Release
.\tests\build\pub_sub_probe.exe --messages 100000
```

`--messages N` 指定每个发布者连续发送的消息数，默认 100000。没有发送间隔。测试固定频道数为 1，分别比较 1 个发布者下 1、4、16 个订阅者，以及 4 个发布者下 1、4、16 个订阅者；这样改变成员数量时，其他负载维度保持可比。每个发布者由独立线程同时启动。

“发布数”是 `Notify` 调用数；“应送达数”是每个频道的发布数乘以该频道订阅者数；“实际处理数”是订阅者工作线程写入可读消息槽的次数。送达率为实际处理数除以应送达数。发布速率按发送阶段计时，处理速率包含发送结束后的排空时间。

为准确统计中间消息，框架的 `Subscriber` 新增只读的 `Accepted_Count()` 和 `Processed_Count()`。前者在消息进入临时槽时增加，后者在工作线程把消息转入可读槽时增加。由于临时槽只能存放一条消息，高频发送时未被接受的消息会被丢弃；测试以所有原本应送达的消息份数为分母，因此会反映这种丢失。

另有 `pub_sub_smoke.exe` 可检查基本类型及频道行为；它不属于主要压力指标。测试在注册完成后才并发发送，订阅者保留到进程退出。
